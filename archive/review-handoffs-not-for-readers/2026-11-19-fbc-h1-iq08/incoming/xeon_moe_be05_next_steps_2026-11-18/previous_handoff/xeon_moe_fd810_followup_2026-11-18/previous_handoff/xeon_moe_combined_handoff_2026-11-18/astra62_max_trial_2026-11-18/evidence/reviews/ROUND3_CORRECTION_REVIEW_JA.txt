1. 結論

06-compact-signed-byte.patch / 07-combined-corrected.patch は、rounding mode によって旧 compact へ戻す修正ではない。生成済み Q8 の実値に -128 が含まれるかを block ごとに記録し、その lane の folded dot で元の PSIGNB の wrap を再現する修正である。

この方針では、F32 入力の folded 選択条件や shared workspace stride が worker の rounding mode に依存しない。従って、懸念していた「worker ごとの丸め状態により400-byteと292-byteの異なる配置を使う」という新しい問題は、この修正には導入されていない。

静的には -128 補正の符号位置、他 lane への非干渉、has_min の初期化、3 IQ 型への適用を確認し、具体的な欠陥を発見しなかった。指摘時と同じ direct 反例を固定した新 DSO で再実行し、4 rounding mode すべてで旧 compact と新 folded の出力 byte が一致した。

通常 nearest の経路にも処理は増えている。prepare では flag 集約、dot では flag load と条件分岐が追加される。新 DSO の逆アセンブルでは3種の dot すべてに、各256要素 block につき has_min load が1回、8 group 分の test + je が残っていた。補正前の通常 nearest の計時を修正版の速度として流用してはいけない。

このレビュー時点では候補実装者の graph rounding 試験の最終結果を受領していない。当担当の実行確認は direct function 比較であり、graph dispatch や多 worker の実行確認を代替しない。

3. -128 の修正内容を独立に確認した理由

xeon-local/folded-input.inc 7–13:
従来の padding[12] の1 byte を has_min に使い、padding を11 bytesへ減らした。group 384 bytes + d 4 bytes + has_min 1 byte + padding 11 bytes =400 bytes。static_assert も400を確認する。

15–31:
Q8 の lo/hi の abs byte を OR 集約し、movemask でいずれかの最上位 bit が立っているかを見る。signed byte の abs 結果で最上位 bit が立つのは元値 -128 の場合のみ。従って has_min は「この block に -128 があるか」を正しく表す。has_min は全 block に対して必ず0または1を書き、過去の padding 内容を読んで判断するわけではない。

65–73:
通常は weight code の sign bit と input sign bit を XOR して符号を入力側から重み側へ移す。has_min がある block では、magnitude の high bit から各 lane の補正 bit を作り、低 nibble の sign bit (bit3) と高 nibble の sign bit (bit7) を OR で立てる。

低 nibble 側の expression は (a0 >> 4) & 0x08。16-bit shift だが、mask 後に残る各 byte の bit3 は同じ元 byte の bit7であり、隣 byte の値に依存しない。高 nibble 側は a1 & 0x80。abs が0…127の lane はどちらの force bit も0となり、同じ block に -128 があっても他の lane の符号は変わらない。

旧 compact dot は abs(weight) × PSIGNB(input, weight) を計算する。input=-128 は weight が正でも負でも PSIGNB 後が -128 となる。修正版は magnitude=128 と強制負符号の weight を掛けるため、同じ積 -128×abs(weight) になる。weight=0 のコードがあっても、正負いずれの LUT 値も0なので積は0のまま。

-128 以外では通常の符号移し替えと一致する。従って各 lane の積が元 compact の積と一致するという形で補正を説明できる。整数 pair sum、scale 適用、FP32 lane 累積と水平和の順番は今回の修正で変えていない。

これは旧 compact 算術の再現を目的とした修正である。旧経路での -128 negation wrap を残すため、数学的な参照値への近さが改善したという意味ではない。

4. 適用範囲と共有 workspace

ggml-cpu.c 1717–1727:
引き続き compact cache が利用でき、use_ref でなく、対象 IQ 型、token 数1、src1=F32 の条件で folded を使う。prequantized Q8 入力は旧 compact のまま。今回 prequantized 入力を新経路へ広げたわけではない。

folded-input.inc 90–96:
IQ3_XXS / IQ2_S / IQ3_S が同じ補正を共有する。実値の -128 を見るため、入力の丸め方や Q8 の生成理由で補正の成否が変わらない。ただし当担当の DSO 実行 fixture は IQ3_XXS の1 block のみであり、3型すべてを実行したと主張しない。

has_min は各変換済み block と同じ400-byte領域内へ書かれる。既存の block 分割で変換する worker が flag も書き、既存 barrier の後に読む。同じ block を読む worker は同じ flag を受け取る。rounding による新たな row_size / nbw0 / pointer offset 分岐は追加されていない。

worker 間で丸め環境を異ならせた時の計算結果全体の再現性を保証する試験は今回行っていない。ただし、この修正に rounding-dependent layout 問題を理由に差戻す根拠は見つからない。
