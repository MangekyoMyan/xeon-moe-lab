設計sketch:

struct TraceCudaEvent {
    cudaEvent_t raw = nullptr;
    ggml_backend_event bridge{};
    uint64_t recorded_generation = 0;
    bool has_record = false;

    // setup時、対象deviceをcurrentにした状態で呼ぶ。hot pathでは呼ばない。
    void init(ggml_backend_t backend) {
        // production実装はerror cleanup、device ownershipを既存方針へ合わせる。
        cuda_check(cudaEventCreateWithFlags(&raw, cudaEventDefault));
        bridge.device = ggml_backend_get_device(backend);
        bridge.context = reinterpret_cast<void *>(raw);
    }

    void record(ggml_backend_t backend, uint64_t generation) {
        // 前のgenerationをharvest済みであることを別のpool stateで検証する。
        ggml_backend_event_record(&bridge, backend);
        recorded_generation = generation;
        has_record = true;
    }

    cudaError_t query(uint64_t generation) const {
        require(has_record && recorded_generation == generation,
                "unrecorded or wrong-generation trace event");
        return cudaEventQuery(raw); // success / not-ready / actual-errorを区別。
    }

    void destroy_after_existing_drain() {
        // HB destructorの既存private_gpu synchronize後、backend free前に呼ぶ。
        // 未完了を救う新しいsyncはここに追加しない。
        if (raw) cuda_check(cudaEventDestroy(raw));
        raw = nullptr;
        has_record = false;
        bridge = {};
    }
};

注:
1. 実際の関数引数順はこの保存版B:946–950の
   ggml_backend_event_record(event, backend)と公開headerを必ず照合する。
   sketchのoriginal_*は説明用placeholderであり、存在する関数名ではない。
2. error時にtiming-only failureを無視して成功記録を作らない。
   CUDA async errorがevent APIから表面化する場合は本来のbackend error処理と整合させる。
3. 同じeventを再recordすると前回記録が置き換わる。前layerのelapsed回収前に再利用しない。
4. 少数4eventを直ちに回収する版が最小。回収を後へ延ばすなら別event poolが必要。
5. event範囲はstream elapsedであり、host CPU区間と足し合わせない。
6. cudaLaunchHostFuncでGPU終了のhost時刻を作る案は採らない。callback自身がstreamを
   止め得るうえ、今回の問に必要なready/not_readyはevent queryで足りる。
7. timing event生成とpinned buffer生成は既存guardの評価対象へ加え、guard値を緩めない。
8. source-only sketchでCUDA Graph/capture対応を実証したと主張しない。
   実装時はtrace-off/onでreplay回数、graph構造、event generation、outputを確認する。
