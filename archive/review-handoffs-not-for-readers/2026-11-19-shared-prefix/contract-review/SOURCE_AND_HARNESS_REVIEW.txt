Private-scratch candidate contract

6. A full single-context plan match precedes submission. Require the frozen text T=1 configuration, one CUDA0 backend and one CPU backend as observed, n_copies=1, callback_eval absent, and the exact eligible layers with immutable device-resident Wgate/Wup/Wdown. Verify the common normalized input by identity, including the CPU copy's source view, weight types and shapes, all strides and operation parameters, the two CPU inputs and their readable host buffers, three host weights and four CPU nodes, then the weighted reduction, unique down consumer and original ADD source order. Reject alternate layouts, dynamic sources, extra consumers, concurrent evaluation/reset and graphs with CUDA stream-region optimization enabled. The normal profile omits GGML_CUDA_GRAPH_OPT. CUDA lines 5210–5224 require it to be 1 to create those regions. Preserve the ordinary route on a failed match before dispatch. After any partial candidate submission an error must drain outstanding CUDA work before tensors can be reused, overwritten or freed.

7. For the reviewed 45f6 CUDA backend, the original tensor identities can be retained throughout. Allocate and initialize three separate F32 output slots in the actual CUDA backend buffer, using backend sizes and alignment. The raw logical data requirement is 27,648 bytes per context. The three original outputs must be canonical, contiguous F32, each with view_src and extra null, view_offs zero, a single matched consumer, no externally live alias-view and no graph output flag. Confirm these for original gate, up and clamp and validate the inputs' CUDA device, strides, original buffer/data pointers and candidate allocation boundaries. GPU F32 tensor initialization has no deferred per-tensor metadata in CUDA lines 799–818. The allocation API requires a fresh tensor with buffer null in base lines 2520–2535. Allocate with separate slot descriptors. During execution the original tensors already own valid bindings and need a scope-bound temporary binding of the data and buffer fields only.

Alternative using the existing allocator

10. After original backend assignment and before split construction, move only the three shared nodes to immediately before the CPU-routed gate, leaving them at the end of the previous GPU split. This arranges the allocator's original norm/ID copy dependencies after the three nodes and keeps the clamp live until down across CPU and weighted reduction. Submit the GPU prefix, perform normal D2H copies, submit the withheld three-node tail, run CPU and join at the existing next H2D. Preserve the separate prefix/tail/remainder CUDA views and UIDs and reject a cross-boundary optimization or concurrent event after CUDA graph_optimize. The other difficulty is plan reuse. The allocator compares per-index sizes, counts and backend types when deciding to reuse a reservation. Its reuse test does not compare DAG topology or live ranges. See ggml-alloc.c lines 997–1048 and 1052–1095, and base lines 2027–2081. A changed ordering or match mask requires an explicitly compatible fresh reservation in both directions. Match and fallback before mutating the graph, or reconstruct and allocate the original schedule before executing a fallback. This additional global reservation contract is the reason for preferring private scratch in this bounded application.
